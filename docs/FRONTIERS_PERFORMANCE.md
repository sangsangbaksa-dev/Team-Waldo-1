# 전장 확장 시뮬레이션 성능

이 기록은 전장 확장에서 변경한 **전략 시뮬레이션의 CPU 시간**을 측정합니다. Three.js 렌더링, 브라우저 입력 처리, WebGL, 에셋 로딩은 포함하지 않습니다. 표의 수치는 실제 FPS나 모든 기기에서의 성능을 보장하지 않습니다.

## 변경 이유와 구현

기존 전투에도 22m 셀의 공간 격자가 있었지만, 모든 병사가 인접 셀의 같은 진영 병사까지 다시 순회했습니다. 대규모 군대가 본부에 모이면 적이 없어도 수백 명의 아군을 반복 검사했습니다. 본부 포탑은 전체 병력을 검색한 뒤 정렬했고, 거점 점령은 거점마다 전체 병력을 순회했습니다. 거점이 9개에서 17개로, 병력이 최대 1,600명으로 늘어나면 이 비용도 증가합니다.

[`src/battle/warSpatial.ts`](../src/battle/warSpatial.ts)의 `WarSpatialIndex`는 다음을 처리합니다.

- 셀과 배열을 매 틱 새로 만들지 않고 재사용합니다.
- 셀 안의 병력을 진영별로 묶고, 적이 없는 셀을 건너뜁니다.
- 본부 포탑과 거점 점령을 근처 셀에서만 조회합니다.
- 이동 중 실제 최대 변위를 기록해 셀 경계를 넘어 거점 안으로 들어온 병력도 같은 틱에 점령에 참여시킵니다.
- 유닛 객체의 현재 체력과 진영 생존 상태를 읽으므로 앞선 공격으로 죽은 병력이 후속 공격이나 점령에 남지 않습니다.

인덱스는 `WeakMap`에 보관하며 저장 데이터에 넣지 않습니다. 이동·충돌·피해량·공격 범위·점령 속도는 이 최적화에서 변경하지 않았습니다.

## 측정 방법

변경 전 `war.ts`는 원격 체크포인트 [`5070908`](https://github.com/sangsangbaksa-dev/Team-Waldo-1/commit/507090867faa801625f903f059b79bc2d75d7ff2)과 동일한 트리의 로컬 커밋 `7e77c21`에서 별도 보관해 같은 실행 프로세스에서 비교했습니다. 공통 지형·전술 지원 모듈은 동일하게 사용했습니다. 원본 코드 복제본은 저장소에 추가하지 않았습니다.

네 가지 조건은 서리 대륙에서 **600명/1,600명 × 집결/혼전**입니다. 집결은 진영별 본부에 배치된 군대, 혼전은 중앙에 네 진영이 함께 밀집한 합성 부하입니다. 병력 수가 표본 사이에 달라지지 않도록 초기 공격 쿨다운을 10초로 두고 AI 판단도 지연했습니다. 실제 공격이 진행되는 검증은 별도로 수행했습니다.

각 조건과 구현을 3회 준비 실행한 다음, 변경 전·후 실행 순서를 번갈아 가며 7회 측정했습니다. 한 표본은 `dt=0.05`의 40틱이며, 보고 값은 **1틱당 CPU 시간의 중앙값**입니다. 초기 상태 생성·추가 훈련·복제 시간은 타이머에 포함하지 않았습니다. 측정 환경과 요약 원본은 [`performance-results.json`](performance-results.json)에 있습니다.

## 결과

| 시작 병력 | 배치 조건 | 변경 전 ms/틱 | 변경 후 ms/틱 | CPU 시간 감소 |
| --- | --- | ---: | ---: | ---: |
| 600명 | 진영별 집결 | 1.373 | 0.465 | 66.1% |
| 600명 | 중앙 혼전 탐색 | 4.075 | 1.800 | 55.8% |
| 1,600명 | 진영별 집결 | 5.336 | 1.315 | 75.4% |
| 1,600명 | 중앙 혼전 탐색 | 27.103 | 12.284 | 54.7% |

혼전 조건은 여러 진영의 병사가 좁은 구역에 겹친 합성 부하이므로 일반 플레이의 평균 프레임 비용을 뜻하지 않습니다. 실제 성능은 군대 분포, 전투 밀도, 맵, 설정, 브라우저와 기기에 따라 달라집니다. 렌더링 성능은 별도의 실제 브라우저 검사로 확인해야 합니다.

## 동작 보존 확인

공격 쿨다운을 0으로 되돌린 네 조건에서 각각 200틱을 실행하고, 변경 전·후 **전체 게임 상태의 JSON이 정확히 같은지** 비교했습니다. 네 조건 모두 일치했습니다. 이 비교에는 유닛 위치·체력·사망·처치 통계·거점 상태·자원·이벤트가 포함됩니다.

거리 동률에는 두 규칙을 보존했습니다. 일반 병력은 기존 셀 순회 순서를 먼저, 같은 셀에서는 원래 유닛 배열 순서를 따릅니다. 본부 포탑은 기존 전체 배열의 안정 정렬과 같이 원래 유닛 배열 순서를 따릅니다.

[`tests/battle/warSpatial.test.ts`](../tests/battle/warSpatial.test.ts)는 진영별 배열에서의 동률, 셀 사이 동률, 포탑의 별도 동률 규칙, 즉시 사망 반영, 인덱스 초기화, 이동 후 점령, 정확한 범위 경계, 같은 틱의 처치·점령·저장 복원을 검사합니다. 기존 장군 및 전술 지원 통합 테스트도 함께 실행합니다.

기본 브랜치 통합 후에는 장군의 활성 이동 기술과 원정 강행군이 겹치는 경우도 추가했습니다. 긴 0.1초 틱에서 이동량이 셀 검색 여유를 넘으면 실제 변위만큼 조회 범위를 넓혀 같은 틱의 적 감지를 유지합니다. 위 성능 표는 이 추가 통합 전의 명시된 측정 조건에서 얻은 기록입니다.

## 현재 소스에서 다시 측정하기

```bash
npm ci
node --import tsx tools/war-benchmark.ts > war-benchmark-results.json
```

[`tools/war-benchmark.ts`](../tools/war-benchmark.ts)는 현재 소스만 측정합니다. 같은 네 조건·준비 횟수·반복 횟수·틱 수를 사용하고, JSON에 중앙값과 표본 값을 기록합니다. 이 명령으로 과거 변경 전 값까지 자동 복원하지는 않습니다. 비교하려면 각 소스 상태에서 같은 조건으로 실행하고 기기·Node 버전·병렬 작업 부하를 맞춰야 합니다.

## 일반 원정 병력 규모

큰 맵에서 세 분대를 운용할 수 있도록 일반 원정의 진영별 병력 상한을 강철 분지 18명, 황혼 변경 30명, 서리 대륙 48명으로 확장했습니다. 수비대 상한은 각각 6·10·16명입니다. AI의 일반 충원 목표도 16·28·46명으로 대응합니다. 모든 일반 원정의 시작 병력은 기존 4명입니다.

대규모 모드는 진영별 400명 상한과 수비대 60명 상한을 유지합니다. 일괄 훈련 API 상한은 일반 원정 5명, 대규모 모드 50명을 유지하며, 상한·자원 검사를 통과하지 못하면 비용을 사용하지 않습니다. 이 규모 확장은 위 비교의 600/1,600명 대규모 조건에는 영향을 주지 않습니다.
