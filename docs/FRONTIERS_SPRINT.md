- 별도의 결정적인 API 봇으로 3맵×일반/군단 **6개 원정, 14,855틱, 307회 불변조건, 59회 전체 저장 복원**을 실행했습니다. 자원·병력 주입 없이 모두 자연 종료했으며 NaN·경계 이탈·상한 초과·승패 불일치·저장 불일치는 없었습니다. 사람 플레이 밸런스나 FPS의 근거가 아닙니다.

## 현재 확인할 항목

1. 통합본의 실제 WebGL 시작, 3개 맵의 일반/군단 모드, 모바일 세로/가로, 작전 지도, 지원, 기록실, 저장 복원을 GitHub Actions로 확인합니다.
2. 소라 장군의 활성 이동 기술과 원정 강행군을 함께 쓴 긴 틱에서 검색 범위를 벗어나는 문제는 재현 후 수정했습니다. 같은 틱의 실제 전투와 저장 복원을 회귀 검사합니다.
3. 스크린샷에서 텍스트 잘림, 스크롤, 버튼 가림, 전장별 색상과 가독성을 점검합니다.
4. Vercel 상태는 빌드 횟수 제한을 보고했습니다. 코드 업로드와 운영 배포를 구분하며, 성공 확인 없이 공개 사이트가 업데이트되었다고 보고하지 않습니다. 요금제 변경은 하지 않습니다.
5. 건물 내부 자원 교환으로 받은 금·식량은 현재 획득 자원 통계에 더하지 않습니다. 총생산과 교환 수령을 어떻게 구분할지 후속 UX 작업에서 정하고, 실제 자원 보유량과 전적의 의미가 어긋나지 않게 문구나 집계를 맞춥니다.

## 후속 작업을 이어갈 때

- 이 브랜치와 PR의 최신 원격 상태를 먼저 읽습니다. 기존 변경을 덮어쓰거나 같은 기능을 중복 추가하지 않습니다.
- 실패한 CI나 실제 조작 문제를 우선 고친 다음, 전장 가독성·맵별 균형·부대 피드백·유용한 편의 기능을 골라 완성합니다. 기존 기능 보존을 확인합니다.
- 코드 변경 후 필요한 범위의 검증을 수행합니다. 최종 묶음은 `npm run lint`, `npm run typecheck`, `npm test`, `npm run validate-data`, `npm run build`를 실행하고 정확한 커밋의 브라우저 검사도 확인합니다.
- 이 환경은 로컬 Chromium의 소켓 생성을 차단했습니다. 자동 승인 검토도 거절했습니다. 제한을 우회하지 말고 GitHub Actions의 실제 브라우저 검사와 아티팩트를 사용합니다.
- Git CLI의 HTTPS 쓰기 인증이 없는 경우 연결된 GitHub의 tree/commit/ref 도구를 사용합니다. 업로드한 tree SHA가 검증한 로컬 tree와 같은지 확인하고, 브랜치 갱신에는 이전 SHA의 lease를 사용합니다. 강제 push로 다른 변경을 제거하지 않습니다.
- 작업마다 이 문서에 변경 내용, 검증한 커밋, 실제 검사 결과, 미해결 항목을 추가합니다. 17:15 KST의 마지막 작업에서는 추가 범위를 벌리지 말고 통합·검증·업로드 결과를 한국어로 정리합니다.
