# SKY WAR 개발 가이드

Team-Waldo-1의 9번째 게임. 다른 게임의 시스템이나 배포 설정을 변경하지 않고 `src/sky/` 안에서 개발합니다.

## 파일 구성

- `game.ts` — 입장/종료, HTML·CSS HUD, 키보드·마우스·터치 조작, 출격·일시정지·리플레이.
- `sim.ts` — `SkySim`: 전투기 비행, AI 웨이브, 총알·미사일·보급품·점수·콤보.
- `view.ts` — `SkyView`: Three.js 월드, 절차적 기체, 카메라, 구름·섬 지형, 입자 풀.
- `visuals.ts` — 기체의 고급 장식과 대기/나무 생성.
- `art.ts` — 캐시된 CanvasTexture, 그래픽 리소스 회수.
- `audio.ts` — AudioEngine 기반 경고음·엔진·효과음.
- `records.ts` — 플레이 횟수, 최고 점수, 웨이브, 격추 기록.
- `quality.ts` — 지속적으로 양호한 FPS에서만 한 단계씩 시각 품질을 복구하는 규칙.
- `sky.css` — 비행 HUD, 타이틀, 모바일 조작 패널.

## 좌표·물리 규칙

- 기체의 로컬 전방은 **-Z**, +Y가 상승 방향입니다.
- 양의 `pitch`는 상승, 양의 `roll`은 오른쪽 날개 하강/우선회입니다.
- `sim.flyJet()`에서 기체 이동은 틱마다 한 번만 수행합니다. 경계 회피도 `stepAI()` 안에서 방향을 선택하며 `flyJet()`을 다시 호출하지 마세요.
- 작전 구역의 수평 경계는 x/z만 제한합니다. 3D 벡터 전체에 배율을 곱하면 고도까지 갑자기 하락합니다.
- 고속 미사일은 단순 종점 거리 대신 **이전 위치 → 현재 위치 선분**으로 충돌을 검사합니다.
- 목표 선행 조준은 양의 교차 시간을 구해 표시합니다. 자동 사격과 HUD의 LEAD 표식은 같은 탄속(`p.speed + 680`)을 사용합니다.
- 게임 종료나 dt≤0이면 `sim.step()`이 더 이상 시간을 진행시키지 않습니다.

## 조작·접근성

- 기본 커서 방식은 **자유(화면 중심 기준 절대 위치)**이며 타이틀의 설정에서 포인터 잠금(상대 이동)으로 바꿀 수 있습니다.
- 키보드 WASD/방향키, Q/E 러더, Shift 부스트, Ctrl 스로틀 감속, Space 사격, M 미사일, F 플레어, C 시점, P 일시정지.
- 휠과 터치패드 스크롤의 `deltaMode`를 정규화하고 Ctrl+휠 확대/축소를 스로틀로 처리하지 않습니다.
- 문서가 비활성화되면 입력을 비우고 자동 일시정지합니다. 장시간 일시정지 후 다시 시작할 때 프레임 갭을 품질 하락으로 오판하지 않습니다.
- 사용자가 동작 감소를 설정한 경우 카메라 흔들림·진동을 억제합니다.

## 성능 관리

- 총알은 최대치와 풀을 유지하고, 불꽃/연기는 인스턴싱으로 렌더링합니다.
- 적기의 고급 장식은 `jetDetail` 그룹 하나로 묶으며 먼 거리에서는 숨깁니다(기본 실루엣·피격 판정은 유지).
- 원근 레벨이 저하되면 대기 구름과 근거리 구름을 **모두** 숨깁니다. 안정적인 FPS가 15초 이상 유지될 때 레벨을 한 단계씩 복구합니다.
- 새 출격에서 폭발 링, 입자 풀, 흔들림, 경고 텍스트 및 이전 세션 입력을 초기화합니다.
- 영구 강화/영구 업그레이드를 추가하지 않습니다.

## 검증

```bash
npx eslint src/sky tests/sky
npm run typecheck
npx vitest run tests/sky
npm run build
npx playwright install chromium --only-shell
node tools/sky-browser-smoke.mjs
```

`.github/workflows/sky-war-validation.yml`은 PR에서 전용 lint·타입·테스트·빌드·Chromium 2종 뷰포트 스모크 테스트를 실행하고 스크린샷을 저장합니다. 기존 전체 `npm run lint`가 다른 게임의 오류 때문에 실패할 수 있으므로, 원인을 분리해서 확인하세요.

테스트가 통과해도 작업 브랜치는 자동으로 병합·프로덕션 배포하지 않습니다.
