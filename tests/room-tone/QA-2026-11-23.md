# ROOM TONE — engineering / QA record (2026-11-23)

Scope: **ROOM TONE only**. This branch is based on the published arcade code
at `8a76a24c58b37dfc45654b36f72bf39fb48ebf08`. No changes to other games,
no deployment, and no automatic merge.

## Changes

- Precise line-of-sight through tile corners; occluded footsteps and proximity
  danger use shortest corridor distance instead of straight-line wall penetration.
- Monster facing cone, fair nearby awareness and stereo-positioned pursuit steps.
- Furniture / equipment collisions, including rotated hiding structures, with
  escape from an already overlapped footprint.
- More stable WebAudio pause/mute/resume and release of the sound graph on unload.
- Responsive render pixel budgets with the hub's low / standard / high quality
  choice; reduced-motion OS and arcade preferences stop camera/capture/flicker.
- Keyboard focus, pause → help → pause navigation, puzzle audio continuity,
  accessible stamina and pursuit states, and modal error announcements.
- Character model loading timeout / cancellation / retry; actionable model,
  damaged asset and WebGL error messages; true elapsed-play clock at low FPS.

## Direct source-level checks completed

- **16,000** fractional-position rays across all four generated chapters matched
  an independent segment-versus-wall-rectangle oracle.
- **20,000** additional randomly selected rays were direction-symmetric.
- Navigation checks on the actual four generated chapter maps found all five
  core objectives and **all 59** procedurally placed hiding spots approachable
  after adding solid props.
- Audio class checks exercised pause/resume/mute/unmute/dispose and delayed
  resume ordering without a zombie heartbeat.
- Model request checks covered deduplicated downloads, abort on release, a

- Render-quality checks sampled 126 viewport / touch conditions, verifying
  finite and ordered low → standard → high pixel resolutions.
- Latest game, assets, audio, helpers and browser smoke script passed

These checks were executed directly against source read from this branch.
They **do not** substitute for the repository's actual Vite build, full Vitest
runner, or Playwright browser execution.

## Required checks before merge/deploy

Run in a checkout of this branch with Node 22:

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install --with-deps chromium --only-shell
node tools/room-tone-browser-smoke.mjs
```

The browser smoke script covers desktop 1280×800 and touch viewports 390×844,
320×640 and 844×390. It also checks first-model-download retry, shared motion
and graphics preferences, keyboard modal focus, paused help navigation,
stamina semantics and simulated WebGL context loss.

Manual playtesting remains important: verify balance when rounding corners,
footstep direction with headphones, joystick capture, hiding visuals,
puzzle answers / all exits, and WebGL performance on real mobile GPUs.
